## Slide 3 — Section: Context windows, context rot, and when to start fresh · Theory

**Moved here from module 1 on 2026-08-26** (was module 1's slide 6). It's a communication-quality concept — knowing when to start a fresh conversation instead of dragging one out — so it sits better next to the 5 Ingredients than in module 1's grounding content. Placed right after slide 2 so the scenario practice that follows can already be run with the "keep sessions fresh" habit in mind; open to moving later in the module (e.g. right before the hands-on) if that reads better once drafted.

**Context windows differ by model.** Every model has a maximum amount it can hold in one conversation, and that ceiling varies across the model lineup — bigger isn't automatically the better default choice for a given task (ties back into module 1's model-selection section).

**Why maxing it out isn't free, even when the ceiling is high.** Two separate costs: it consumes tokens (and tokens cost money at volume, relevant to module 3's tier/policy content), and — regardless of budget — reliability on information from earlier in a long conversation degrades the longer that conversation runs, even though the window technically still holds it. That's context rot: not a bug, a property of how these models attend to long input.

**The practical rule participants leave with:** several shorter, focused conversations beat one sprawling thread. When a chat has drifted across multiple unrelated tasks, when it's carrying a lot of dead weight from earlier turns, or when outputs start ignoring instructions given early on — that's the signal to start a new session rather than push the same one further. This is also the real justification for module 7's Projects, not just a convenience feature.
