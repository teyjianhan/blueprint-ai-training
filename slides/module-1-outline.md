## Slide 4 — Section: Is using AI at work "cheating"? · Theory

Not in the source course outline — added to name the quiet objection some participants walk in with, before it becomes a distraction later.

**The frame:** a bad manager dumps a task on a junior with no context, no check-in and no review, then blames the junior when it comes back wrong. A good manager briefs properly, discusses the approach, and reviews the work together — the junior grows, and so does the output. Using AI works the same way. Handing AI a vague ask and shipping whatever comes back unreviewed is the bad-manager pattern; briefing it properly and checking its work (modules 2 and 9) is the good-manager pattern.

**The reframe:** the question isn't "is AI allowed" — it's "am I managing it well." Delegation was never cheating when done with a junior; it isn't cheating done with AI either, as long as the same judgement gets applied.

## Slide 6 — Section: Context windows, context rot, and when to start fresh · Theory

Not in the source course outline — added as the direct, practical follow-on from slide 5's context explanation.

**Context windows differ by model.** Every model has a maximum amount it can hold in one conversation, and that ceiling varies across the model lineup — bigger isn't automatically the better default choice for a given task (ties back into slide 7's model-selection content).

**Why maxing it out isn't free, even when the ceiling is high.** Two separate costs: it consumes tokens (and tokens cost money at volume, relevant to module 3's tier/policy content), and — regardless of budget — reliability on information from earlier in a long conversation degrades the longer that conversation runs, even though the window technically still holds it. That's context rot: not a bug, a property of how these models attend to long input.

**The practical rule participants leave with:** several shorter, focused conversations beat one sprawling thread. When a chat has drifted across multiple unrelated tasks, when it's carrying a lot of dead weight from earlier turns, or when outputs start ignoring instructions given early on — that's the signal to start a new session rather than push the same one further. This is also the real justification for module 7's Projects, not just a convenience feature.
